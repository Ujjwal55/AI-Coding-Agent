# DTDL Hackathon - Current Architecture & Features

This document provides a high-level overview of the current system architecture and the features that have been implemented so far. It is designed to quickly onboard another AI model or developer onto the current state of the codebase.

## 1. System Architecture

The project is built on a modern, asynchronous stack bridging a visual React interface with a Python-based AI agent orchestrator.

### Frontend
- **Framework**: Next.js 14 (App Router) with React 18
- **Visual Editor**: `React Flow` (`@xyflow/react`) is used to render the drag-and-drop node canvas.
- **Styling**: Tailwind CSS, utilizing flexbox/grid for the IDE-like layout (Node Library, Canvas, Inspector Panel, Run Console).

### Backend
- **Framework**: FastAPI (Python)
- **Database**: SQLite (via SQLAlchemy async `AsyncSession`)
- **Agent Orchestrator**: **LangGraph**. Used to define stateful, cyclical workflows for the AI agents.
- **Execution Sandbox**: The `Executor` node uses `asyncio.create_subprocess_shell` to spawn real bash commands (e.g., `claude-code`, tests) in an isolated `target_repo/` directory and captures STDOUT/STDERR.

### State Management & Persistence
- **Graph State**: Managed by LangGraph's `GraphState` (TypedDict).
- **Checkpointer**: LangGraph's `MemorySaver` is implemented in a centralized `runtime.py` to allow the graph to pause (interrupt) execution mid-flight and resume later.
- **Database Models**: 
  - `Workflow`: High-level metadata.
  - `WorkflowVersion`: Stores the raw JSON generated by React Flow.
  - `WorkflowRun`: Stores execution status (`running`, `paused`, `completed`, `failed`) and the JSON state snapshot.

## 2. Features Implemented

### Dynamic Graph Compilation
- **Feature**: The system does not use a hardcoded LangGraph sequence. It features a `Dynamic Graph Compiler` (`backend/orchestrator/graph.py`).
- **How it works**: It parses the exact nodes and edges exported by React Flow, matches them to Python functions via a `NODE_MAP`, and dynamically wires up `add_edge` and `add_conditional_edges` to build the `StateGraph` on the fly.

### Node Inspector Configuration
- **Feature**: A dynamic right-side panel in the UI.
- **How it works**: Clicking a node on the canvas opens the inspector. Users can configure node-specific settings like:
  - **Model**: Select between GPT-4o, Claude 3.5 Sonnet, etc.
  - **System Prompt**: Custom instructions injected into the node's state.
  - **Max Retries**: For validation routing.
  - **Execution Command**: Specifically for the Executor node (e.g., `pytest`, `claude-code run --plan="plan.md"`).

### Success Criteria Agent (Hybrid Mode)
- **Feature**: Converts engineering objectives into measurable criteria, with human oversight.
- **How it works**: The graph starts with an Objective and flows into the `Criteria` node. Once the AI generates the criteria, LangGraph utilizes `interrupt_before=["planner"]` to pause execution. The frontend detects this `paused` state and displays a **Hybrid Mode Modal**, allowing the user to manually edit the criteria text. Clicking "Approve" hits a `/resume` API endpoint to inject the new state and continue.

### Decision Node & Complex Routing
- **Feature**: Deterministic routing based on validation outcomes.
- **How it works**: The `Validator` node outputs a `validation_status` and `confidence_score`. The `Decision` node uses this state to route conditionally:
  - If `FAIL` and attempts < max retries -> Route to `Planner` (Retry loop).
  - If `FAIL` and attempts >= max retries -> Route to `End` (Safe Stop).
  - If `confidence_score` < 0.8 -> Route to `Human Approval`.
  - Else -> Route to `End` (Success).

### Execution State Manager
- **Feature**: Centralized run management (`backend/orchestrator/runtime.py`).
- **How it works**: Handles the actual `ainvoke` of LangGraph. Manages the injection of the `MemorySaver` checkpointer and properly handles `thread_id` to ensure API requests can safely pause and resume the exact state of a specific `WorkflowRun`.

## 3. Pending Features (Track B Roadmap)
*These are features yet to be built to complete the hackathon requirements:*
- **Execution Timeline & Node Inspection**: Streaming actual node outputs, STDOUT logs, and execution times to the frontend Run Console.
- **Workflow Export/Import**: Hooking up UI buttons to download/upload the React Flow JSON configuration.
- **Session History & Human Approval Queue**: UI pages to view past database `WorkflowRuns` and a dashboard for pending `human_approval` pauses.
- **Better Demo Experience**: Making the React Flow nodes turn Green/Red/Yellow in real-time as the backend executes them.
